## 1. Типы данных. Объявление переменных и констант

**Ответ.** Тип данных определяет допустимые значения переменной и операции над ними. В Java есть восемь примитивных типов и ссылочные типы. Примитивная переменная содержит само значение, ссылочная — ссылку на объект или `null`. Переменная объявляется указанием типа и имени. Модификатор `final` запрещает повторное присваивание значения переменной.

**Тип · Размер значения · Значения / назначение**

• `byte` — 8 бит — -128...127
• `short` — 16 бит — -32 768...32 767
• `int` — 32 бита — -2^31...2^31-1
• `long` — 64 бита — -2^63...2^63-1
• `float` — 32 бита — Числа с плавающей точкой; около 6–7 значащих десятичных цифр
• `double` — 64 бита — Числа с плавающей точкой; около 15–16 значащих десятичных цифр
• `char` — 16 бит — Кодовая единица UTF-16, 0...65 535
• `boolean` — Не установлен спецификацией языка — `true` или `false`

К ссылочным типам относятся, например, классы (`String`, `Scanner`), интерфейсы и массивы. Примитивы не могут содержать `null`.

```java
int count;              // объявление
count = 12;             // присваивание
int x = 3, y = 8;        // объявление с инициализацией
long population = 8_000_000_000L;
float fraction = 1.5F;
boolean ready = true;
char letter = 'J';
String language = "Java";
final int LIMIT = 100;
var score = 10;          // компилятор выводит тип int
```

`var` применяется к локальным переменным с инициализатором; тип остаётся фиксированным. Это не динамическая типизация. Локальную переменную необходимо инициализировать перед чтением. Поля и элементы новых массивов получают значения по умолчанию: числовой ноль, `false`, `null` и т. п.

Для констант уровня класса обычно пишут `static final`, например `static final double PI = 3.14159;`. Имена констант принято записывать в `UPPER_CASE`.

**Уточнение к лекциям.** Верхняя граница знакового целого — `2^(n-1) - 1`. Размер `boolean` нельзя указывать как гарантированный один бит. `final` у ссылки запрещает заменить ссылку, но не делает сам объект неизменяемым:

```java
final int[] numbers = {1, 2};
numbers[0] = 9;            // допустимо
// numbers = new int[3];   // ошибка компиляции
```

Эти уточнения подтверждаются JLS разд. 4.2 и разд. 4.12.4 (docs.oracle.com).

## 2. Ввод / вывод

**Ответ.** Для консольного вывода используют `System.out` и методы `print()` и `println()`. Первый печатает без перевода строки, второй завершает строку. Для ввода можно создать `Scanner`, связанный с `System.in`, и читать значения методами `nextInt()`, `nextDouble()`, `next()` и `nextLine()`.

```java
import java.util.Scanner;

class InputExample {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Возраст: ");
        int age = sc.nextInt();
        sc.nextLine(); // читаем остаток строки после числа
        System.out.print("Имя: ");
        String name = sc.nextLine();
        System.out.println(name + ", возраст: " + age);
    }
}
```

**Метод · Что читает**

• `nextInt()` — Следующее целое типа `int`
• `nextDouble()` — Следующее число типа `double`
• `next()` — Следующий токен; по умолчанию до пробельного разделителя
• `nextLine()` — Остаток текущей строки без её завершающего разделителя

**Что важно объяснить.** После `nextInt()` перевод строки обычно остаётся непрочитанным. Поэтому следующий `nextLine()` может вернуть пустую строку. В примере дополнительный вызов читает этот остаток. Если после числа на той же строке были данные, он прочитает и их.

Неподходящий формат числа может вызвать `InputMismatchException`. Для предварительной проверки есть `hasNextInt()`. Разделитель дробной части при `nextDouble()` зависит от локали сканера. Эти особенности описаны в документации Scanner (docs.oracle.com).

## 3. Класс String

**Ответ.** `String` — класс для представления строк. Строка является объектом, и её содержимое после создания не изменяется. Операции, которые дают изменённый текст, возвращают строку с результатом. Для сравнения содержимого используют `equals()`, для лексикографического порядка — `compareTo()`.

```java
String s = "Java";
System.out.println(s.length());            // 4
System.out.println(s.charAt(0));           // J
System.out.println(s.equals("Java"));      // true
System.out.println(s.equalsIgnoreCase("JAVA")); // true
System.out.println(s.substring(1, 3));     // av
String result = s + " language";
System.out.println(s);                     // Java
```

**Метод · Назначение**

• `length()` — Длина в кодовых единицах UTF-16
• `charAt(i)` — Кодовая единица `char` по индексу `i`
• `equals(other)` — Равенство содержимого
• `equalsIgnoreCase(other)` — Равенство без учёта регистра
• `compareTo(other)` — Отрицательное число, ноль или положительное число при сравнении
• `indexOf(part)` — Индекс первого вхождения или `-1`
• `lastIndexOf(part)` — Индекс последнего вхождения или `-1`
• `startsWith(prefix)` / `endsWith(suffix)` — Проверка начала / конца
• `substring(from, to)` — Подстрока: индекс `from` включён, `to` исключён

Индексы начинаются с нуля. Например, `"Java".charAt(4)` выходит за границы строки.

**Уточнение к лекции.** `compareTo()` не обязан возвращать ровно `-1` или `1`: важен знак результата. `"Java".equals("Java")` даёт `true`. Оператор `==` для ссылок проверяет, указывают ли они на один объект; он не заменяет `equals()`. Один символ вне базовой многоязычной плоскости Unicode занимает в строке две позиции `char`. См. документацию String (docs.oracle.com).

## 4. Массивы


**Ответ.** Массив — объект, содержащий фиксированное количество элементов одного объявленного типа. Переменная массива хранит ссылку на него. Массив можно создать через `new` с указанием длины или через инициализатор. Элементы доступны по индексам от нуля до `length - 1`, длина находится в поле `length`.

```java
int[] values = new int[3];  // {0, 0, 0}
values[0] = 10;
int[] numbers = {2, 4, 6};
for (int i = 0; i < numbers.length; i++) {
    System.out.println(numbers[i]);
}
for (int number : numbers) {
    System.out.println(number);
}
```

Объявление `int[] a;` само по себе массив не создаёт. После создания длина конкретного массива не меняется. Можно создать другой массив и присвоить ссылку на него переменной.

Двумерный массив — массив ссылок на массивы. Строки могут иметь разную длину:

```java
int[][] matrix = {{1, 2}, {3, 4, 5}};
for (int i = 0; i < matrix.length; i++) {
    for (int j = 0; j < matrix[i].length; j++) {
        System.out.println(matrix[i][j]);
    }
}
```

`matrix.length` — количество строк, `matrix[i].length` — длина строки. При `new int[2][]` внутренние массивы ещё не созданы: элементы внешнего массива равны `null`.

**Частые ошибки.** У массива пишут `length`, у строки — `length()`. Выход за допустимый индекс вызывает `ArrayIndexOutOfBoundsException`. Присваивание `int[] b = numbers;` не копирует элементы: обе переменные указывают на один массив. Слово «динамический» в лекции относится к созданию массива во время выполнения; автоматического изменения длины у обычного массива нет.

## 5. Классы

**Ответ.** Класс описывает данные и поведение объектов. Данные представлены полями, поведение — методами. Объект, или экземпляр класса, создаётся выражением `new` с вызовом конструктора. Конструктор инициализирует объект, имеет имя класса и не имеет возвращаемого типа, даже `void`.

```java
class Point {
    private int x;
    private int y;

    Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
    Point() {
        this(0, 0);
    }
    int getX() {
        return x;
    }
    double distanceTo(Point other) {
        double dx = (double) x - other.x;
        double dy = (double) y - other.y;
        return Math.sqrt(dx * dx + dy * dy);
    }
}
```

Применение в методе: `Point p = new Point(3, 4);`. Переменная `p` содержит ссылку на созданный объект. `this` обозначает текущий объект; `this.x` позволяет отличить поле от одноимённого параметра. Вызов `this(...)` обращается к другому конструктору того же класса.

**Инкапсуляция** объединяет данные и методы и ограничивает прямой доступ к внутреннему состоянию. Например, `private` скрывает поля, а методы предоставляют контролируемые операции. Это не означает, что абсолютно все поля любого класса обязательно должны быть закрыты.

**Перегрузка**, называемая в лекции «совмещением», — несколько методов с одним именем и разными списками параметров: количеством, типами или порядком типов. Изменить только тип результата недостаточно. Перегружать можно и конструкторы.

Если конструкторов в обычном классе нет, компилятор объявляет конструктор по умолчанию без параметров. Если уже объявлен хотя бы один конструктор, дополнительный конструктор без параметров автоматически не появляется.

## 6. Наследование

**Ответ.** Наследование позволяет создать подкласс на основе существующего суперкласса, добавить свои данные и методы и переопределить унаследованное поведение. В Java класс может непосредственно наследовать только один класс. Для этого используют `extends`.

```java
class Person {
    private String name;
    Person(String name) {
        this.name = name;
    }
    void displayInfo() {
        System.out.println("Имя: " + name);
    }
}
class Employee extends Person {
    private String company;
    Employee(String name, String company) {
        super(name);
        this.company = company;
    }
    @Override
    void displayInfo() {
        super.displayInfo();
        System.out.println("Компания: " + company);
    }
}
```

Здесь `Person` — суперкласс, `Employee` — подкласс. `super(name)` вызывает конструктор родителя, `super.displayInfo()` — его реализацию метода. Переопределение в лекции также называется «замещением».

Конструкторы не наследуются и не переопределяются: подкласс объявляет свои. Если явного вызова другого конструктора нет, обычно неявно вызывается `super()`. Поэтому при отсутствии подходящего доступного конструктора родителя без параметров нужен явный вызов с аргументами.

Приватные члены родителя не наследуются как доступные члены подкласса; приватное состояние родительской части объекта доступно через методы родителя. Если у класса не указан суперкласс, для обычного класса им является `Object`.

**Дополнение из лекции о модификаторах.** От `final`-класса наследоваться нельзя. `sealed`-класс ограничивает допустимых прямых наследников; `permits` может перечислять их явно.

## 7. Полиморфизм

**Ответ.** Полиморфизм позволяет работать с объектами разных подклассов через общий тип родителя или интерфейса. При вызове переопределённого экземплярного метода выполняется реализация фактического класса объекта. Выбор этой реализации происходит во время выполнения.

```java
class Animal {
    void speak() {
        System.out.println("Звук");
    }
}
class Cat extends Animal {
    @Override
    void speak() {
        System.out.println("Мяу");
    }
}
class Dog extends Animal {
    @Override
    void speak() {
        System.out.println("Гав");
    }
}
```

Применение в методе:

```java
Animal[] animals = {new Cat(), new Dog()};
for (Animal animal : animals) {
    animal.speak(); // сначала Мяу, затем Гав
}
```

У переменной `animal` объявленный тип `Animal`, а фактические объекты имеют типы `Cat` и `Dog`. Компилятор проверяет доступность метода через объявленный тип; во время выполнения выбирается реализация объекта. Через ссылку родителя нельзя просто вызвать дополнительный метод, объявленный только в подклассе.

**Механизм · Что меняется · Когда выбирается**

• Перегрузка — Список параметров методов с одним именем — Во время компиляции
• Переопределение — Реализация унаследованного экземплярного метода — Во время выполнения по фактическому объекту

**Уточнение к лекции.** Перегрузка не выбирается JVM по фактическим типам аргументов во время выполнения. Статические методы скрываются, а не переопределяются; поля тоже не участвуют в динамическом выборе методов. См. JLS разд. 8.4.8–8.4.9 (docs.oracle.com).

## 8. Модификаторы доступа

**Ответ.** Модификаторы доступа определяют, откуда разрешено обращаться к классу или его членам. Есть `public`, `protected`, `private` и доступ внутри пакета при отсутствии модификатора.

**`public`**
   Внутри объявляющего класса: Да
   Другой класс того же пакета: Да
   Подкласс другого пакета: Да
   Посторонний класс другого пакета: Да

**`protected`**
   Внутри объявляющего класса: Да
   Другой класс того же пакета: Да
   Подкласс другого пакета: Да, с ограничениями
   Посторонний класс другого пакета: Нет

**Без модификатора**
   Внутри объявляющего класса: Да
   Другой класс того же пакета: Да
   Подкласс другого пакета: Нет
   Посторонний класс другого пакета: Нет

**`private`**
   Внутри объявляющего класса: Да
   Другой класс того же пакета: Нет*
   Подкласс другого пакета: Нет
   Посторонний класс другого пакета: Нет

Таблица предполагает, что сам содержащий класс доступен. *Вложенные классы внутри одного общего класса верхнего уровня могут обращаться к приватным членам друг друга.*

Доступ без модификатора называют package-private или доступом по умолчанию. Слово `default` для его объявления не пишут. У класса верхнего уровня можно указать `public` либо не указывать модификатор доступа; `private` и `protected` применимы к классам-членам, но не к классам верхнего уровня.

**Тонкость `protected`.** Из подкласса другого пакета к экземплярному `protected`-члену нельзя обращаться через произвольную ссылку типа родителя. Такой доступ разрешён через `this`, `super` или подходящую ссылку типа этого подкласса / его наследника. См. JLS разд. 6.6.2 (docs.oracle.com).

Другие модификаторы из лекции имеют иное назначение:

- `static`: член принадлежит классу; статический метод не имеет `this`.
- `final` у переменной: нельзя повторно присвоить значение; у метода: нельзя переопределить; у класса: нельзя наследовать.
- `abstract`: класс или метод содержит абстракцию без полной реализации.
- `sealed`: ограничен набор прямых наследников.

## 9. Абстрактные классы

**Ответ.** Абстрактный класс объявляется с `abstract` и предназначен для использования как общая основа подклассов. Непосредственно создать его экземпляр нельзя. Он может содержать поля, конструкторы, обычные методы и абстрактные методы — объявления без тела. Конкретный подкласс обязан реализовать все оставшиеся абстрактные методы.

```java
abstract class Figure {
    abstract double area();
    void printArea() {
        System.out.println("Площадь: " + area());
    }
}
class Circle extends Figure {
    private double radius;
    Circle(double radius) {
        this.radius = radius;
    }
    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}
```

Применение: `Figure f = new Circle(2); f.printArea();`. Создан объект `Circle`, а переменная имеет тип `Figure`. Метод `printArea()` общий, но вызов `area()` использует реализацию круга.

Если подкласс оставляет абстрактный метод без реализации, он тоже должен быть `abstract`. Абстрактный класс может не иметь ни одного абстрактного метода. Его конструктор вызывается при создании подкласса.

Абстрактный метод заканчивается `;`, а не пустым телом `{}`. Он не может быть `private`, `static` или `final`: эти модификаторы несовместимы с требованием реализации в подклассе. Класс не может одновременно быть `abstract` и `final`.

## 10. Нестатические внутренние классы

**Ответ.** Нестатический внутренний класс-член объявляется в теле другого класса без `static`. Каждый его объект связан с конкретным экземпляром внешнего класса. Внутренний класс может напрямую обращаться к полям и методам этого экземпляра, включая `private`.

```java
class Outer {
    private String message = "Привет";
    class Inner {
        void show() {
            System.out.println(message);
        }
    }
}
```

Создание и вызов в методе:

```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();
inner.show(); // Привет
```

В экземплярном методе `Outer` можно написать `new Inner()`, поскольку внешний объект уже есть. Если имена совпали, `Outer.this` обозначает внешний объект, а `this` — текущий внутренний.

Применение: вспомогательная сущность, связанная с состоянием конкретного внешнего объекта. Например, часть составного объекта или внутренний обработчик. Нужно помнить, что внутренняя сущность удерживает связь с внешним экземпляром.

Не следует заучивать старое утверждение, что внутренний класс вообще не может иметь статические члены: в современных версиях Java это ограничение снято. Для данного вопроса главное — наличие связи с экземпляром внешнего класса. См. JLS разд. 8.1.3 (docs.oracle.com).

## 11. Статические внутренние классы

**Ответ.** Точное название — **статический вложенный класс**. Он объявляется внутри другого класса с `static` и не связан с конкретным экземпляром внешнего класса. Для его создания внешний объект не нужен.

```java
class Container {
    private static String title = "Контейнер";
    private int size = 5;

    static class Info {
        void show(Container container) {
            System.out.println(title);
            System.out.println(container.size);
        }
    }
}
```

Применение в методе:

```java
Container.Info info = new Container.Info();
info.show(new Container());
```

Статический вложенный класс может иметь собственные обычные и статические члены. Модификатор `static` у самого класса не делает все его методы статическими.

**Уточнение к лекции.** Нельзя напрямую использовать нестатическое поле внешнего класса без объекта. Но через явно полученную ссылку на внешний объект обращаться к нему можно, в том числе к приватному полю, как в примере.

**Признак · Внутренний класс-член · Статический вложенный класс**

• Связь с внешним экземпляром — Есть — Нет
• Создание снаружи — `outer.new Inner()` — `new Outer.Nested()`
• Доступ к полям внешнего объекта — Через неявную связь — Через явно указанную ссылку

## 12. Локальные и анонимные вложенные классы

**Ответ.** Локальный класс имеет имя и объявляется внутри блока, например метода; использовать его имя можно в пределах соответствующей области видимости. Анонимный класс не имеет имени и объявляется одновременно с созданием объекта. Он удобен для однократной реализации интерфейса или переопределения поведения класса.

Локальный класс внутри метода:

```java
class LocalExample {
    void run() {
        String greeting = "Привет";
        class Printer {
            void print() {
                System.out.println(greeting);
            }
        }
        Printer printer = new Printer();
        printer.print();
    }
}
```

Анонимный класс, реализующий интерфейс:

```java
Runnable task = new Runnable() {
    @Override
    public void run() {
        System.out.println("Задача выполняется");
    }
};
task.run();
```

`new Runnable() { ... }` создаёт объект анонимного класса, реализующего `Runnable`. Это не непосредственное создание экземпляра интерфейса. В случае `new SomeClass(...) { ... }` создаётся объект анонимного подкласса.

**Что важно объяснить.** Захватываемые локальные переменные должны быть `final` или effectively final: после инициализации им не присваивают другое значение. Явно писать `final` необязательно. Это ограничение относится к переменной, а не к неизменности объекта, на который она ссылается.

Локальный класс в статическом методе не получает внешний экземпляр. Анонимный класс не может объявить собственный конструктор. Через переменную типа интерфейса доступны методы этого интерфейса; произвольный дополнительный метод анонимного класса через неё вызвать нельзя.

**Исправление структуры примеров лекции.** Создание локального класса должно находиться в его области видимости. Переопределённые методы анонимного класса располагают внутри фигурных скобок после `new`, а выражение создания заканчивают `;`.

## 13. Интерфейсы

**Ответ.** Интерфейс задаёт контракт поведения: какие операции должен предоставлять реализующий его класс. Объявляется через `interface`, реализуется через `implements`. Один класс может реализовывать несколько интерфейсов, сохраняя единственный суперкласс.

```java
interface Printable {
    void print();
    default void printTwice() {
        print();
        print();
    }
}
class Report implements Printable {
    @Override
    public void print() {
        System.out.println("Отчёт");
    }
}
```

Применение: `Printable p = new Report(); p.printTwice();`. Переменная интерфейсного типа может ссылаться на объект любого класса, реализующего интерфейс.

Обычный метод интерфейса без тела неявно `public abstract`. Реализующий метод должен быть `public`. Если конкретный класс не реализует все обязательные методы, он должен быть абстрактным. Поля интерфейса неявно `public static final` и должны иметь инициализаторы.

Интерфейс может наследовать несколько интерфейсов: `interface C extends A, B { ... }`. Тогда реализация `C` должна выполнять и унаследованные требования. Метод `default` имеет тело и может быть переопределён классом.

**Уточнение к лекции.** Интерфейс может содержать реализацию: помимо `default`, существуют статические и приватные методы. Приватные методы служат внутренними помощниками; они не являются публичным контрактом. См. JLS, глава 9 (docs.oracle.com).

**Абстрактный класс · Интерфейс**

• Общее состояние экземпляров и поведение — Общий контракт поведения
• Может иметь поля экземпляра и конструкторы — Нет конструкторов и полей экземпляра
• Один непосредственный суперкласс — Класс может реализовать несколько интерфейсов
• Может содержать абстрактные и обычные методы — Может содержать абстрактные, `default`, статические и приватные методы

## 14. Исключения (try, catch, finally)

**Ответ.** Исключение — объект, представляющий ошибочную или иную особую ситуацию, которая прерывает обычное выполнение кода. В `try` помещают контролируемые операции, `catch` обрабатывает подходящее исключение, `finally` выполняет завершающие действия при выходе из `try`/`catch`.

```java
try {
    int[] numbers = {5, 0};
    int result = numbers[0] / numbers[1];
    System.out.println(result);
} catch (ArithmeticException ex) {
    System.out.println("Деление на ноль");
} catch (ArrayIndexOutOfBoundsException ex) {
    System.out.println("Неверный индекс");
} finally {
    System.out.println("Расчёт завершён");
}
```

В примере после целочисленного деления на ноль оставшиеся операторы `try` пропускаются. Выполняется первый подходящий `catch`, затем `finally`. Если обработка завершилась нормально, выполнение продолжается после всей конструкции.

Обработчик подходит, если его параметр имеет тип выброшенного исключения или его суперкласса. Более конкретные обработчики располагают перед общими: `catch (Exception ex)` перед `catch (ArithmeticException ex)` сделал бы второй блок недостижимым. При отсутствии подходящего обработчика исключение распространяется по стеку вызовов.

Иерархия:

```text
Object
  - Throwable
      - Error
      - Exception
          - RuntimeException
```

**Дополнение для понимания `throws`.** Проверяемые исключения необходимо обработать или объявить. `RuntimeException`, `Error` и их подклассы — непроверяемые. `Error` обычно означает серьёзную проблему исполнения; технически его можно перехватить, но обычная прикладная обработка, как правило, на это не рассчитана. Необработанное исключение завершает текущий поток; завершение всей программы зависит от остальных потоков. См. JLS, глава 11 (docs.oracle.com).

**Уточнение.** `finally` выполняется и при нормальном выходе, и обычно при `return` или распространении исключения. Но он не гарантирован при завершении JVM, например через `System.exit()`, или аварийном прекращении процесса. Не стоит помещать туда `return`: он может скрыть исключение или заменить ранее подготовленный результат. Есть также multi-catch: `catch (ArithmeticException | ArrayIndexOutOfBoundsException ex)`. Для закрытия ресурсов часто используют `try` с ресурсами. См. JLS разд. 14.20 (docs.oracle.com).

## 15. Исключения (throw, throws)

**Ответ.** `throw` — оператор, который непосредственно выбрасывает конкретный объект исключения. `throws` — часть объявления метода или конструктора, перечисляющая типы исключений, которые могут передаваться вызывающему коду. `throws` самостоятельно ничего не выбрасывает и не обрабатывает.

```java
static int requirePositive(int value) throws Exception {
    if (value <= 0) {
        throw new Exception("Значение должно быть положительным");
    }
    return value;
}
```

Вызов в другом методе:

```java
try {
    int value = requirePositive(-2);
    System.out.println(value);
} catch (Exception ex) {
    System.out.println(ex.getMessage());
}
```

`new Exception(...)` создаёт объект; `throw` выбрасывает его. Обычное выполнение текущего участка прекращается, и начинается поиск обработчика. `getMessage()` возвращает сообщение исключения.

**`throw` · `throws`**

• В теле метода или другом допустимом блоке — В объявлении метода / конструктора
• После него выражение, например `new Exception(...)` — После него типы, например `IOException, SQLException`
• Выполняет выбрасывание — Объявляет возможное распространение

Если проверяемое исключение не обработано в методе, его нужно объявить через `throws`; вызывающий код тоже должен обработать его или передать обязанность выше. Для непроверяемого исключения объявление необязательно:

```java
static void checkAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Возраст не может быть отрицательным");
    }
}
```

**Уточнение к лекции.** Правильно `throws Exception` в объявлении метода, а не `throw Exception`. Не требуется перечислять абсолютно все возможные непроверяемые исключения. См. JLS разд. 11.2 (docs.oracle.com).

## 16. Пользовательские классы исключений

**Ответ.** Собственный класс исключения создают, чтобы явно обозначить ошибочную ситуацию предметной области, передать дополнительные данные и обрабатывать её отдельно от других ошибок. Для проверяемого исключения обычно наследуются от `Exception`, для непроверяемого — от `RuntimeException`.

Полный пример с проверяемым исключением:

```java
class FactorialException extends Exception {
    private final int number;
    FactorialException(String message, int number) {
        super(message);
        this.number = number;
    }
    int getNumber() {
        return number;
    }
}

class FactorialExample {
    static long factorial(int number) throws FactorialException {
        if (number < 0 || number > 20) {
            throw new FactorialException(
                "Для типа long допустимы аргументы от 0 до 20", number);
        }
        long result = 1;
        for (int i = 2; i <= number; i++) {
            result *= i;
        }
        return result;
    }
    public static void main(String[] args) {
        try {
            System.out.println(factorial(6));  // 720
            System.out.println(factorial(0));  // 1
            System.out.println(factorial(-3)); // исключение
        } catch (FactorialException ex) {
            System.out.println(ex.getMessage());
            System.out.println("Аргумент: " + ex.getNumber());
        }
    }
}
```

Конструктор исключения передаёт сообщение родителю через `super(message)` и сохраняет дополнительное поле. Метод `factorial()` объявляет возможность распространения исключения через `throws`, а при неверном аргументе выбрасывает его через `throw`. Вызывающий метод перехватывает именно `FactorialException`.

**Уточнение к лекции.** Факториал нуля равен единице. В цикле нужно умножать на `i`, а не на `1`. Для `long` значение `20!` помещается, а `21!` уже нет; ограничение предотвращает переполнение. Собственные исключения не обязаны непосредственно наследоваться только от `Exception`: базовый класс выбирают по смыслу и требованиям к проверке обработки.

## Что особенно важно не перепутать

1. `String.equals()` сравнивает содержимое, `==` у ссылок — тождество объектов.
2. Перегрузка выбирается при компиляции; переопределённая реализация — при выполнении.
3. Конструкторы не наследуются и не переопределяются.
4. `final` у ссылки не запрещает менять состояние объекта.
5. Длина массива фиксирована; `length` — поле.
6. Внутреннему классу-члену нужен внешний экземпляр; статическому вложенному — нет.
7. Захват локальной переменной допускает effectively final без явного `final`.
8. В интерфейсе бывают методы с реализацией.
9. `throw` выбрасывает объект; `throws` перечисляет типы.
10. `finally` выполняется при обычном выходе из конструкции, но не гарантирован при прекращении JVM.
