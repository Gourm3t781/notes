# Ответы к коллоквиуму по базам данных

Лекция 1 в подборке отсутствует, поэтому ответы 1–4 сформулированы по списку вопросов. В ответах 5–30 использованы формулировки со слайдов, где они есть.

### Лекция 1. Базы данных и СУБД

1. **База данных** — организованная совокупность взаимосвязанных данных. **Схема** описывает их структуру и ограничения, **текущее состояние** — данные в конкретный момент. **Тип** задаёт вид значений и допустимые операции, **домен** — множество допустимых значений атрибута. **Метаданные** описывают данные, а **системный каталог** хранит метаданные об объектах базы. Контекст определяет смысл значения, например его единицу измерения.
2. **Модель данных** задаёт структуру данных, операции над ними и ограничения допустимых состояний. Реляционная модель использует отношения, документная — документы, графовая — вершины и рёбра, «ключ–значение» — пары уникального ключа и значения. **Анализ требований** выявляет нужные данные, операции и правила. **Концептуальное проектирование** описывает предметную область, **логическое** строит схему в выбранной модели, **физическое** определяет способы хранения и доступа.
3. **СУБД** — программа для управления базами данных. **База данных** — сами данные, **сервер базы данных** — процесс СУБД, принимающий запросы клиентов. СУБД выполняет запросы, проверяет ограничения и права, управляет транзакциями и восстанавливает данные после сбоев. Встроенная СУБД работает внутри приложения, клиент-серверная — отдельным процессом, а в многослойной архитектуре между клиентом и СУБД есть сервер приложения.
4. **ANSI/SPARC** выделяет внешний уровень представлений пользователей, концептуальный уровень общей логической схемы и внутренний уровень хранения. Отображения связывают соседние уровни и позволяют преобразовывать запросы и результаты. **Физическая независимость** позволяет менять хранение без изменения логической схемы, **логическая** — менять логическую схему с сохранением внешних представлений, если их можно воспроизвести.

### Лекция 2. ER-модель

5. **ER-модель** описывает сущности, их свойства и связи. **Тип сущности** задаёт общие свойства, **экземпляр** — конкретный объект, **множество сущностей** — все рассматриваемые экземпляры типа. **Атрибут** описывает свойство, **домен** задаёт допустимые значения, **идентификатор** однозначно определяет экземпляр. В нотации Чена тип сущности обозначают прямоугольником, связь — ромбом, атрибут — овалом, идентификатор подчёркивают. Сначала выделяют сущности, атрибуты и идентификаторы, затем связи, роли и ограничения, после чего проверяют модель по требованиям.
6. **Связь** выражает отношение между сущностями. **Степень связи** — число ролей участников, **роль** показывает, кем выступает участник. В рекурсивной связи один тип сущности участвует в разных ролях. При **1:1** с обеих сторон не более одного соответствия, при **1:N** одному экземпляру A могут соответствовать многие B, а каждому B — не более одного A, при **M:N** множественные соответствия возможны с обеих сторон. Пара `(min,max)` задаёт число участий одного экземпляра. Минимум 0 означает необязательное участие, минимум 1 — обязательное.
7. **Тернарная связь** описывает один совместный факт с тремя участниками. Атрибут сущности описывает сам объект, атрибут связи — совместное участие объектов. При выделении связи в отдельную сущность каждый её экземпляр должен ссылаться на всех трёх участников и сохранять атрибуты, уникальность и ограничения исходной связи. Независимые попарные связи могут породить лишние тройки.

### Лекция 3. Даталогическое моделирование

8. **Тип сущности** преобразуют в отношение, его атрибуты — в столбцы, выбранный идентификатор — в первичный ключ. Для **1:N** внешний ключ размещают на стороне N. Для **1:1** внешний ключ размещают на одной стороне и добавляют `UNIQUE`. Если участие стороны, где размещён внешний ключ, обязательно, добавляют `NOT NULL`.
9. **Связь M:N** преобразуют в отдельное отношение с двумя внешними ключами и атрибутами связи. Если каждой паре соответствует один факт, пара внешних ключей образует составной первичный ключ либо защищается `UNIQUE` и `NOT NULL` при отдельном первичном ключе. Обязательное участие каждого экземпляра хотя бы в одной связи проверяют отдельным ограничением.
10. **Рекурсивную связь 1:N** реализуют внешним ключом на ту же таблицу, а **рекурсивную M:N** — таблицей связи с двумя ссылками на неё в разных ролях. **Тернарную связь** представляют отдельной таблицей с тремя внешними ключами и атрибутами связи. Состав ключа определяют по правилам связи. Проверяют, что строки сохраняют совместные факты, а ограничения — исходную уникальность и обязательность участия.

### Лекция 4. Реляционная модель данных

11. **Отношение** — множество кортежей одной схемы. **Схема** задаёт имя отношения, атрибуты и их домены. **Кортеж** описывает один факт, **атрибут** — именованное свойство, **домен** — множество допустимых значений. **Степень** — число атрибутов, **кардинальность** — число кортежей. Значения атомарны, кортежи уникальны, порядок кортежей и именованных атрибутов несущественен. SQL-таблица может допускать дубликаты строк и `NULL`.
12. **Суперключ** однозначно определяет кортеж в любом допустимом состоянии. **Потенциальный ключ** — суперключ, из которого нельзя убрать атрибут без потери уникальности. **Первичный ключ** — поле или минимальный набор полей, выбранный для однозначного определения записи в таблице. **Альтернативные ключи** — остальные потенциальные ключи. **Простой** ключ состоит из одного поля, **составной** — из нескольких. **Естественный** ключ берут из предметной области, **суррогатный** создают специально для идентификации. **Внешний ключ** — поле или набор полей, ссылающийся на ключ той же или другой таблицы.

### Лекция 5. Целостность и операции

13. **Целостность сущностей** требует уникальности первичного ключа и запрещает `NULL` в любом его компоненте. **Ссылочная целостность** требует, чтобы заполненный внешний ключ указывал на существующую запись. При вставке и обновлении проверяют итоговые значения, а при удалении записи или изменении её ключа учитывают зависимые ссылки. `RESTRICT` запрещает операцию при наличии ссылок, `CASCADE` переносит изменение ключа или удаляет зависимые строки, `SET NULL` очищает ссылку, `SET DEFAULT` ставит значение по умолчанию.
14. `PRIMARY KEY` задаёт уникальный обязательный ключ, `FOREIGN KEY` проверяет ссылки, `UNIQUE` запрещает повторение заданных значений, `NOT NULL` требует наличия значения, `CHECK` проверяет условие. `NULL` означает отсутствие значения, а обычное сравнение с `NULL` даёт `UNKNOWN`. `CHECK` отклоняет `FALSE`, поэтому для обязательности поля отдельно задают `NOT NULL`.
15. **Выборка** оставляет кортежи по условию, **проекция** оставляет заданные атрибуты и удаляет повторы, **переименование** меняет имена без изменения значений. **Объединение** берёт кортежи хотя бы из одного отношения, **пересечение** — из обоих, **разность** — из первого при их отсутствии во втором. Эти три операции требуют совместимых схем. **Замкнутость** означает, что результат операции снова является отношением и может участвовать в следующей операции.

### Лекция 6. Нормализация отношений

16. **Функциональная зависимость** `X → Y` означает, что одинаковым значениям `X` всегда соответствуют одинаковые значения `Y`. Зависимости задаются правилами предметной области, а потенциальный ключ минимален и определяет все атрибуты. **Аномалия добавления** мешает сохранить факт отдельно, **аномалия обновления** требует менять несколько копий факта, **аномалия удаления** приводит к потере другого факта. **Нормализация** уменьшает избыточность и устраняет вызванные ею аномалии.
17. **1НФ** требует одного атомарного значения в каждой ячейке и отсутствия повторяющихся групп. **2НФ** требует 1НФ и полной зависимости каждого непервичного атрибута от каждого потенциального ключа. **Первичный атрибут** входит хотя бы в один потенциальный ключ, **непервичный** — ни в один. При полной зависимости нужен весь ключ, при частичной достаточно его части.
18. **3НФ** требует, чтобы для каждой нетривиальной зависимости `X → A` набор `X` был суперключом либо атрибут `A` входил хотя бы в один потенциальный ключ. Зависимость нетривиальна, если `A` не входит в `X`. Например, цепочка «ключ → код отдела → название отдела» нарушает 3НФ, если код отдела не суперключ, а название — непервичный атрибут. Для устранения нарушения код и название выносят в отдельное отношение. 3НФ включает требования 2НФ.
19. **Порядок нормализации** — выявить зависимости и все потенциальные ключи, проверить 1НФ–3НФ, выполнить декомпозицию и проверить отсутствие потерь, сохранение зависимостей, ключи и ссылки. Суррогатный ключ упрощает идентификацию, а ограничения предметной области задают отдельно.

### Лекция 7. НФБК и завершение нормализации

20. **НФБК** требует, чтобы левая часть каждой нетривиальной функциональной зависимости была суперключом. В 3НФ допустима и зависимость на первичный атрибут. **Замыкание `X⁺`** — все атрибуты, которые определяет `X`. Потенциальный ключ — минимальный набор, замыкание которого содержит все атрибуты. При нарушающей зависимости `X → Y` схему `R` делят на `X ∪ Y` и `R − (Y − X)`, затем проверяют обе части.
21. **Декомпозиция без потерь** позволяет естественным соединением частей точно восстановить исходное отношение. Для бинарного разложения достаточно и необходимо, чтобы общие атрибуты функционально определяли хотя бы одну из частей. **Сохранение зависимостей** означает, что из зависимостей отдельных частей выводятся все исходные зависимости. В 3НФ можно обеспечить оба свойства, а в НФБК всегда можно обеспечить разложение без потерь, но сохранение всех зависимостей возможно не всегда.
22. **Многозначная зависимость** `X ↠ Y` означает, что при фиксированном `X` набор значений `Y` не зависит от значений остальных атрибутов. **4НФ** требует, чтобы слева каждой нетривиальной многозначной зависимости стоял суперключ. **Зависимость соединения** требует, чтобы отношение восстанавливалось соединением заданных проекций. **5НФ** требует, чтобы каждая нетривиальная зависимость соединения следовала из потенциальных ключей. **НФДК** требует, чтобы все ограничения отношения следовали из ограничений доменов и ключей.
23. **Денормализация** — преднамеренное введение избыточности для ускорения чтения, например хранение копий или вычисленных значений. Выигрыш в чтении сопоставляют с затратами хранения и согласованного обновления. **Материализованное представление** хранит результат запроса и обновляется по заданным правилам. **Вертикальное разбиение** распределяет столбцы по таблицам с общим ключом и может сохранять нормальные формы.

### Лекция 8. Реляционная алгебра

24. **Декартово произведение** образует все пары кортежей, **соединение по условию** оставляет из них пары, удовлетворяющие условию. **Эквисоединение** использует условие равенства, **естественное соединение** сравнивает все одноимённые атрибуты и оставляет каждый общий атрибут один раз. При самосоединении два вхождения одного отношения различают переименованием или псевдонимами. Несколько отношений соединяют последовательным применением соединений.
25. **Внутреннее соединение** оставляет только совпавшие пары. **Левое**, **правое** и **полное внешние соединения** дополнительно сохраняют строки без пары слева, справа или с обеих сторон соответственно, заполняя отсутствующие поля `NULL`. `ON` определяет совпадения, `WHERE` фильтрует уже полученные строки и оставляет только `TRUE`. `DISTINCT` удаляет повторы результата.
26. **Деление** `R(X,Y) ÷ S(Y)` возвращает значения `X` из `πX(R)`, для которых в `R` есть пара с каждым `Y` из `S`. Формула деления — `C − πX((C × S) − R)`, где `C = πX(R)`. При пустом делителе результат равен `C`. В SQL это выражают через двойное `NOT EXISTS`, беря кандидатов из `SELECT DISTINCT X FROM R`.

### Лекция 9. Реляционное исчисление и SQL

27. **Кортежное реляционное исчисление** задаёт запрос в форме `{t | F(t)}`, где переменные обозначают кортежи, а формула состоит из предикатов, связок и кванторов. Свободная переменная задаёт кортеж результата, связанная используется в области своего квантора. `∃` означает «существует», `∀` — «для всех». В SQL состав результата задаёт `SELECT`, кандидатов — `FROM`, условия — `WHERE`, а существование — `EXISTS`.
28. `EXISTS` истинен при наличии хотя бы одной строки подзапроса, `NOT EXISTS` — при её отсутствии. **Коррелированный подзапрос** использует значения текущей строки внешнего запроса. `AND` требует выполнения обеих проверок, `OR` — хотя бы одной. `EXISTS` не размножает внешнюю строку при нескольких совпадениях, а `JOIN` может. Если совпадения нет, но результат подзапроса содержит `NULL`, `NOT IN` может дать `UNKNOWN`.
29. **Всеобщий квантор** означает, что условие выполняется для каждого элемента области проверки. Двойное `NOT EXISTS` проверяет отсутствие элемента, для которого нет подтверждения условия. Внешний запрос задаёт кандидатов, вложенный — область проверки. Если область проверки пуста, проходят все кандидаты.
30. **Доменное реляционное исчисление** использует переменные отдельных значений атрибутов. Общая переменная в предикатах связывает отношения по равенству значений. **Безопасное выражение** ограничивает переменные данными отношений и константами запроса, а результат не зависит от расширения внешнего домена. Неограниченное отрицание может вывести результат за эту область. **Реляционная полнота** — способность выразить любой запрос реляционной алгебры. Безопасные кортежное и доменное исчисления эквивалентны ей по выразительной силе.
